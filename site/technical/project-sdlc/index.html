⌘ Specification v0.0.2

SDLC Engine

A generic, deterministic, fully implementable software engine for managing the complete development lifecycle as an event-sourced state machine with parallel orchestration.

Core Concepts

Event-Sourced State Machine

Every state change is an immutable event. Replayable from any checkpoint. Total ordering per work item. No hidden state.

Parallel Star Topology

Hub coordinates, agents execute. Kanban boards with WIP limits. Optimistic concurrency. DAG-based dependency unblocking.

Self-Regulating Guards

Anti-fixation guards at every layer. Mutation tests, stranger tests, adversarial reviews. Guards fire on every state entry — can BLOCK or REDIRECT.

Emergent Architecture

Refactoring and harvesting detect common patterns, extract libs, promote to SOA services, and spawn child SDLC instances — autonomously.

TDD — The Inner Loop

Strict RED → GREEN → REFACTOR discipline. NOT_STARTED → GREEN is forbidden. A node MUST pass through RED (a real failing test) before GREEN. Skipping RED is completion theater.

TDD StateDefinition
NOT_STARTEDNo test file yet. tdd.test-file is null.
REDTest exists and fails. Spec requirement not yet implemented, or regression.
GREENTest exists and passes.
REFACTORTests stay green while implementation is cleaned up.

Legal: NOT_STARTED → RED → GREEN → REFACTOR. Backward: GREEN|REFACTOR → RED on TEST_FAIL / CODE_REGRESSION.

RGB Feedback Loop

The self-improvement loop. Tests don't just make code better — they make specs, features, strategy, motivation, and drivers better. When tests expose problems beyond code, feedback escalates upward through the hierarchy.

ColorEventTargetScope
REDCODE_REGRESSIONSPECLocal fix — immediate
GREENINTEGRATION_FLAWFEAT / ARCHMid-level redesign — 1 sprint
GREENUNFEASIBLE_SCOPET-MOTISolution unviable — 1 sprint

§5 — Deterministic Engine Core
