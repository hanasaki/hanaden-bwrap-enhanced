VFS Topology & Namespace Isolation

The security boundary is the mount namespace itself. Visibility is the only access control. What the process can't see, it can't touch.

VFS Filesystem Layout

What is a VFS? A Virtual Filesystem (VFS) is a kernel abstraction layer that presents a unified directory tree to a process, regardless of what physical storage — or no storage at all — backs each mount point. Linux mount namespaces allow each process to see its own VFS, completely independent of the host. V-Universe exploits this: every sandbox gets a purpose-built VFS where --ro-bind, --tmpfs, and --bind mounts compose a custom root that the kernel enforces — no application-level checks required. The process literally cannot address paths that aren't in its VFS.

When bwrap-enhanced.sh start executes, it constructs a complete VFS visible only to the contained process. The host filesystem is never directly accessible. The diagram below shows the macro-level mapping: which host zones are exposed (read-only or read-write), which are masked with volatile tmpfs, and which are injected synthetically via file descriptors.

What's Visible

  • Host /usr, /lib, /lib64 — read-only
  • Synthetic /etc/passwd and /etc/group — injected via memory FDs
  • DNS resolution (/etc/resolv.conf) and CA certs (/etc/ssl)
  • One writable home directory (controlled egress point)
  • Ephemeral tmpfs for /tmp, /var/tmp, /dev/shm

What's Invisible

  • Host home directory (~/.ssh, ~/.aws, ~/.gnupg)
  • Host /root, /var, /opt, /srv
  • Other users' home directories
  • Host /run (D-Bus, Wayland, PipeWire — unless opted in)
  • Network (unless --net-passthrough)
  • Environment variables (unless --env-passthrough)

Initialization Sequence

The start subcommand constructs the sandbox through a deterministic sequence. Every step is validated before proceeding — failures are never silent.

PID 1 Foreground Hold

Inside the sandbox, the contained command runs as PID 1. The parent shell uses a zero-poll /proc-based watcher to maintain the foreground hold:

Key insight: No polling loop. The watcher uses inotifywait or tail -f /dev/null --pid=$PID to block until the child exits. Zero CPU overhead during normal operation.

When the contained process exits:

  • All tmpfs mounts evaporate (kernel-managed cleanup)
  • The mount namespace is destroyed (kernel-managed cleanup)
  • The user namespace is destroyed (kernel-managed cleanup)
  • No artifacts remain on the host filesystem
  • The exit code of the contained process propagates to the caller

Passthrough Architecture

Each passthrough flag selectively binds host resources into the sandbox. Privilege escalation follows a strict ordering: absent < ro < rw

FlagTypeHost ResourceSandbox MountImplied By
--net-passthrough bool Network namespace Share host network —
--wayland-passthrough bool $XDG_RUNTIME_DIR/$WAYLAND_DISPLAY Wayland socket bind implies --x11-passthrough
--audio-passthrough bool $XDG_RUNTIME_DIR/pipewire-0 PipeWire socket bind —
--x11-passthrough bool /tmp/.X11-unix X11 socket bind implied by wayland/gnome/kde
--dbus-passthrough bool Session D-Bus socket D-Bus bind NEVER implied — always explicit
--mise-passthrough graded ~/.local/share/mise ro or rw bind —
--local-bin-passthrough graded ~/.local/bin ro or rw bind —
