Technical Drivers

Why We Built It This Way

The technical constraints and design drivers that shaped V-Universe's architecture.

Driver: Rootless by Requirement

The fundamental constraint: containment must work without root privileges. This eliminates Docker, LXC, and traditional chroot. What remains:

  • User namespaces (Linux 3.8+): Unprivileged processes can create isolated namespaces
  • Bubblewrap (bwrap): Minimal, audited, setuid-free sandbox tool designed for exactly this use case
  • No kernel modules: Everything uses stock kernel capabilities available on any modern Linux

Design decision: We chose bubblewrap over other sandboxing tools because it's the only one that provides full mount/PID/user namespace isolation without requiring root, a daemon, or kernel modules.

Driver: Single Script Deployment

Containment tools with complex installation procedures create adoption barriers. Design constraints:

  • One file: The entire sandbox is one bash script. Copy it, run it, done.
  • No compilation: Bash + coreutils. Nothing to build, link, or compile.
  • No package manager: No pip install, no npm install, no apt-get. Just a file.
  • No configuration files: All configuration via CLI flags and environment variables.

Driver: Zero Side Effects

The sandbox must not leave traces on the host filesystem. This is both a security requirement and an operational one:

What Zero Means

  • No temp files during setup
  • No PID files
  • No lock files
  • No log files on host
  • Identity via memory file descriptors

Why It Matters

  • Concurrent sandboxes don't collide
  • Crash leaves no orphaned state
  • No cleanup required after execution
  • No TOCTOU race conditions
  • Deterministic from first invocation

Driver: Deterministic Behavior

Same inputs must produce same outputs. Every invocation of V-Universe with identical flags creates an identical sandbox:

  • No hidden state: No config files, caches, or databases influence behavior
  • Fail-fast: Invalid configuration fails immediately with clear error, not silently
  • Idempotent: Running the same command twice produces the same result
  • Testable: Determinism enables comprehensive automated testing — 875+ tests verify this
