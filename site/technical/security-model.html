Security Model

The Constitution

The security model is codified in CONSTITUTION.md — a binding governance document that defines invariants, articles, and enforcement rules. Every code change must satisfy the Constitution or be rejected.

Article II — The Immutable Principle

§1 External Construction

The jailer designs and provisions the jail before execution. All sandbox parameters are resolved and validated before exec bwrap is called.

§2 External Enforcement

The Linux kernel enforces the mount namespace boundary. No application-level checks. No honor-system restrictions. The kernel is the guard — not the code.

§3 Zero Self-Policing

Never trust or enable a prisoner to build their own cell, alter their confines, or enforce rules upon themselves. The sandbox config is invisible to the contained process.

Security Invariants

These invariants MUST hold at all times. Each is verified by executable specifications.

IDInvariantMechanism
SI-01 Host root filesystem is never writable from inside the sandbox --ro-bind for all host mounts
SI-02 Sandbox startup produces zero host filesystem artifacts FD-injected identity, no temp files
SI-03 Network is denied unless explicitly opted in via --net-passthrough --unshare-net (default)
SI-04 Environment is clean unless explicitly opted in via --env-passthrough --clearenv (default)
SI-05 D-Bus is never implicitly passed through --dbus-passthrough must be explicit; never implied by other flags
SI-06 Sandbox identity is synthetic — never matches host user /dev/fd/N bind for /etc/passwd and /etc/group
SI-07 All tmpfs mounts evaporate when sandbox exits Kernel-managed tmpfs lifecycle
SI-08 Misconfiguration causes loud failure, never silent degradation Fail-fast validation before exec bwrap

Threat Model

ThreatAttack VectorMitigationInvariant
Credential exfiltration Read ~/.ssh/, ~/.aws/ Path not mounted → invisible SI-01
Host filesystem modification Write to host /etc, /usr Read-only bind mounts SI-01
Startup artifact persistence Temp file left on host after crash FD-injected identity, no disk writes SI-02
Network exfiltration Curl/wget to external server --unshare-net by default SI-03
Environment harvesting Read $AWS_SECRET_KEY etc. --clearenv by default SI-04
D-Bus lateral movement Send messages to host services D-Bus never implied, always explicit SI-05
Identity spoofing Process claims to be host user Synthetic /etc/passwd via FD SI-06

Key insight: The mount namespace IS the security boundary. If a file or socket isn't mounted into the namespace, it doesn't exist from the perspective of any process inside. This is not "access denied" — it's "path does not exist." There is no error message to reverse-engineer, no permission boundary to probe.
