Security Architecture

Security Is the Architecture

The mount namespace is the security boundary. If a file isn't mounted, it doesn't exist. Not "access denied" — invisible.

The Immutable Principle

What It Means

The foundational security axiom — derived from physical security: prisons are designed by people who will never be inside them.

  • Sandbox config defined before the contained process starts
  • Contained process cannot modify its own boundaries
  • Kernel enforces boundaries — not the application
  • No process inside can see or modify sandbox config

What It Prevents

  • Self-policing: Processes that promise not to access paths
  • Honor-system: Env vars that suggest limits
  • App-level ACLs: Permission checks malicious code can bypass
  • Config escape: Processes modifying sandbox config

If the prisoner can see the lock, the jail is broken.

Five Security Tiers

Start at Tier 0 (maximum isolation) and opt in to exactly what each workload needs.

Tier 0

Maximum Isolation

Clean env, network deny, no GUI. AI agents, untrusted scripts.

Tier 1

GUI + Audio

Wayland + PipeWire. Browsers, editors inside sandbox.

Tier 2

+ Accessibility

AT-SPI bus for screen readers.

Tier 3

+ D-Bus Portals

File picker portals. Can prompt user for host files.

Tier 4

+ DE Services

GNOME/KDE full desktop integration.
