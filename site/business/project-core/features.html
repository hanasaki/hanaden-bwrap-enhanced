Everything You Need to Contain

Comprehensive containment without compromising functionality.

🔒

Mount Namespace Isolation

Every sandbox gets its own virtual filesystem. The contained process sees a complete Linux environment — /usr, /bin, /etc — but it's all read-only from the host. The process literally cannot see files outside its boundaries.

  • Read-only root with host /usr, /lib, /bin bind-mounted
  • Private /tmp, /var/tmp, /dev/shm via tmpfs
  • Controlled egress via explicit bind-mounts
  • Synthetic identity: /etc/passwd, /etc/group injected via memory FDs
💨

Zero Side Effects

V-Universe never writes to the host during sandbox creation. No temp files, no PID files, no lock files. Everything via file descriptors.

  • /etc/passwd and /etc/group via /dev/fd/N — zero disk writes
  • All tmpfs mounts vanish when sandbox exits
  • No startup artifacts left on host even on crash
  • Fail-fast on misconfiguration — never silently degrades
🖥

Desktop GUI Passthrough

Run full graphical applications inside the sandbox — browsers, editors, IDEs.

  • Wayland — native compositor socket
  • X11 — XWayland compatibility
  • PipeWire — audio passthrough
  • Accessibility — AT-SPI bus for screen readers
  • D-Bus portals — file picker, notifications (opt-in only)
🔧

Developer Toolchain Integration

Pass through specific tools without exposing the entire host. Privilege grading: absent < ro < rw.

  • mise — runtime version manager (ro/rw)
  • ~/.local/bin — custom tooling (ro/rw)
  • Network passthrough flag for connected workloads
  • Environment variable passthrough (explicit opt-in)
⌨

Professional CLI Interface

Multi-subcommand dispatcher following git/systemctl pattern.

  • provision — create virtual root skeletons
  • fsck — verify and repair sandbox integrity
  • start — launch isolated processes
  • Dry-run and validate modes for safe testing

Every feature backed by executable specifications — real behavioral verification.

  • 875 test assertions across 42 feature suites
  • Structured test IDs traceable to SDLC specifications
  • JUnit/JaCoCo/HTML reporting pipeline
  • Parallel execution with configurable job count
