# SandboxEntrypoint: Final exec_sandbox() Tail Call

## Specification Statement

The last executable line of `bwrap-enhanced.sh` MUST be:

```bash
exec_sandbox "$CLEAR_ENV" "$VIRTUAL_USER_NAME" "$HOST_REAL_ROOT_DIR" "$HOST_REAL_HOME_DIR" "${TARGET_CMD[@]}"
```

This call MUST occur:
1. After all three validation guards pass (EmptyCommandFatal, MissingRootFatal, MissingHomeFatal)
2. With all 5 arguments in the specified order
3. As a tail-call — `exec_sandbox()` itself uses `exec bwrap` internally, so no code after this line ever executes

## Rationale

`exec_sandbox()` is the sole entry point into the bwrap namespace. All CLI parsing,
validation, and default application is preparatory setup for this single call.
The argument order is the stable API contract between the top-level CLI and the
`exec_sandbox()` function:

1. `CLEAR_ENV` — passed as `$1` to control `--clear-env` / `--unshare-all` flag
2. `VIRTUAL_USER_NAME` — passed as `$2` for identity injection
3. `HOST_REAL_ROOT_DIR` — passed as `$3` (the virtual root)
4. `HOST_REAL_HOME_DIR` — passed as `$4` (the egress home)
5. `"${TARGET_CMD[@]}"` — passed as `$5...$N` (the command to run)

Because `exec_sandbox()` uses `exec bwrap ...` internally (via the `os.execv`
self-regeneration pattern), the current process image is replaced and no shell
code after this line can execute. This guarantees no post-sandbox cleanup code
can accidentally mutate host state.

## Constraints

| Constraint | Value | Condition |
|------------|-------|-----------|
| Call position | Last executable line of script | Always |
| CLEAR_ENV | $1 to exec_sandbox | Always |
| VIRTUAL_USER_NAME | $2 to exec_sandbox | Always |
| HOST_REAL_ROOT_DIR | $3 to exec_sandbox | Always |
| HOST_REAL_HOME_DIR | $4 to exec_sandbox | Always |
| TARGET_CMD[@] | $5..N to exec_sandbox | Always |
| Post-call code | MUST NOT exist (exec replaces shell) | Always |
