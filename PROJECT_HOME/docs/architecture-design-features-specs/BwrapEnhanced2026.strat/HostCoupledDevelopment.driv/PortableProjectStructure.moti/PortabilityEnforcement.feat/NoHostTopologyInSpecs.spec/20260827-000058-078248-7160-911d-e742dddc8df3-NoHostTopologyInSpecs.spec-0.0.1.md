# NoHostTopologyInSpecs: Specs Describe Behavior Not Host Mechanisms

## Specification Statement

Specification documents (`.spec`, `.feat`, `.driv`, `.moti` `.md` files in the
docs/architecture-design-features-specs tree) MUST describe observable sandbox
behavior in terms of the sandbox's own parameters. Specs MUST NOT reference:

- autofs mount mechanisms
- NFS (Network File System) specifics
- Host filesystem topology external to sandbox parameters
- Host-specific mount timeout behavior

## Exceptions

- Security bulletins (`.secbul`) -- historical records of incidents
- The `HostCoupledDevelopment.driv` doc itself -- describes the problem being solved
- Analysis documents (`.analys`) that explicitly study host behavior
- Brainstorming documents

## Rationale

Specs are behavioral contracts. They define WHAT the system does, not WHY
the host behaves a certain way. Host-specific knowledge (autofs hangs, NFS
storms) is implementation context that belongs in analysis docs, not in
testable specifications. When specs bake in host knowledge, they become
untestable on hosts with different topologies.

## Constraints

| ID | Constraint | Condition |
|----|-----------|-----------|
| NHT-C1 | Spec docs contain zero `autofs` references (excl. exceptions) | Always |
| NHT-C2 | Spec docs contain zero `NFS`/`nfs` references (excl. exceptions) | Always |
| NHT-C3 | Spec docs describe behavior in terms of sandbox parameters only | Always |
