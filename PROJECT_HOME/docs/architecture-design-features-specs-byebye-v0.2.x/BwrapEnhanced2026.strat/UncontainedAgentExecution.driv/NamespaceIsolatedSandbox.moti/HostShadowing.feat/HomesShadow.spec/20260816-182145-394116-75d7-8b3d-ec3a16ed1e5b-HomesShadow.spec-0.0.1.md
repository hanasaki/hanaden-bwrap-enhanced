# HomesShadow: /homes Host Mount Trigger Shadowed by Empty tmpfs

## Specification Statement

When the host has `/homes` present as a mount path, the sandbox MUST overlay it with
`--tmpfs /homes`, presenting an empty tmpfs inside the sandbox. Access to any path
under `/homes` inside the sandbox MUST complete immediately (< 1 second) with
"No such file or directory" -- NOT trigger a remote network filesystem probe that may hang.

## Rationale

Many production Linux systems use `/homes` (distinct from `/home`) as a mount
point for remote user home directories. When `bwrap --bind HOST_ROOT /` binds the
host root, `/homes` would be visible inside the sandbox as an unshadowed trigger. Any
`ls /homes/anyuser` inside could cause the system daemon to send a remote mount request
to a remote server -- which can take 30-90 seconds to timeout on an unreachable server,
or permanently mount the remote volume if reachable.

This is especially dangerous in AI agent workloads where the agent may iterate over
filesystem paths. A single `ls /homes` inside a loop would cause severe latency and
could accidentally mount hundreds of remote volumes.

## Constraints

| Constraint | Value | Condition |
|------------|-------|-----------|
| /homes filesystem type inside sandbox | tmpfs | Always (when host has /homes) |
| /homes contents inside sandbox | empty | Always |
| Remote probes triggered by /homes access | 0 | Always |
| Access time to /homes | < 0.5 seconds | Always |

## Measurement Method

```bash
# Inside sandbox:
stat -f -c %T /homes          # Expected: tmpfs
ls /homes                     # Expected: empty
time ls /homes/nonexistent 2>&1  # Expected: < 0.5s (not 30s timeout)

# On host: verify no remote mount was triggered
mount | grep -iE 'remote|cifs|smb|sshfs|fuse' | wc -l   # Before == After (no new remote mounts)
```
