# ForegroundHold: Sandbox Lives Until All Children Exit, Preserving CMD Exit Code

## Rationale

GUI applications use fork-exec-parent-exits: the launcher exits immediately, leaving
the GUI as an orphan child of PID 1. Without the hold loop, the sandbox namespace
would be destroyed immediately after the launcher exits — killing the GUI app.
The hold loop ensures the namespace stays alive until ALL children exit, without ever
calling external commands (which would appear in /proc/1/task/1/children and create an
infinite loop).
