# Generic SDLC Bash Testing Specification

## 0. Purpose and Scope

This document defines the **standard testing architecture, execution protocol, and reporting schema** for all Bash shell scripts, libraries, CLI entry points, and automation tooling within the Hanaden AI ecosystem and generic deterministic SDLC engines.

All shell test suites MUST:
1. Use **`bats-core`** (Bash Automated Testing System) as the authoritative test framework.
2. Emit machine-readable, structured test results formatted as **JSON Lines (`jsonl`)**.
3. Integrate with the SDLC event-sourced state machine to enable deterministic quality gates, regression tracking, and anti-reward-hacking validation.

---

## 1. Test Framework Standard: `bats-core`

All Bash testing MUST be implemented using `bats-core` (and standard helper libraries), ensuring test isolation, subshell safety, and standardized assertion primitives.

### 1.1 Core Requirements

- **Runner Requirement:** Test suites MUST execute under `bats` (version >= 1.10.0 recommended).
- **Subshell Isolation:** Every `@test` block runs inside an isolated subshell; side effects (environment variables, temporary file creation, trap handlers) MUST be cleaned up in `teardown()` or managed inside transient temporary directories.
- **Helper Libraries:** Suites requiring advanced assertions, file checks, or mock helpers MUST utilize:
  - `bats-support` — supporting library for standard test output formatting
  - `bats-assert` — common assertions (`assert_success`, `assert_failure`, `assert_output`, `assert_equal`, `refute_output`)
  - `bats-file` — filesystem assertions (`assert_file_exist`, `assert_dir_exist`, `assert_file_permission`)

### 1.2 Test File Conventions

- Test files MUST reside in the corresponding `src/test/...` or component test directories.
- Test files MUST have the `.bats` extension or be executed via standardized runner scripts.
- Each test MUST have a unique identifier and descriptive name mapping directly to an SDLC `SPEC` constraint.

```bash
#!/usr/bin/env bats

setup() {
    load 'test_helper/bats-support/load'
    load 'test_helper/bats-assert/load'
    export TEST_TMPDIR="$(mktemp -d)"
}

teardown() {
    rm -rf "${TEST_TMPDIR}"
}

@test "BT-001: bwrap-enhanced exits with error when root dir is missing" {
    run bwrap-enhanced ctrl --root-dir "/nonexistent/path/$(uuidgen)" -- /bin/true
    assert_failure
    assert_output --partial "ERROR"
}
```

## 2. Structured Emission Standard: JSONL (JSON Lines)

Test runners MUST stream/emit test execution events as line-delimited JSON objects (`jsonl`), where each newline represents a discrete, self-contained event or test result record.

### 2.1 Rationale for JSONL

- **Streamability:** Immediate line-by-line consumption without in-memory buffering of massive full-suite arrays.
- **Fault-Tolerant Ingestion:** Abrupt test runner crashes or timeouts retain all preceding emitted test results up to the crash point.
- **Deterministic Replay:** Individual test records can be replayed and ingested by the SDLC Event Bus directly into the event store.

### 2.2 JSONL Event Types

The test execution stream MUST produce records conforming to one of the following `event_type` schemas:

1. `suite_started`: Emitted once at the beginning of a test suite execution.
2. `test_case`: Emitted immediately upon completion of each individual `@test` case.
3. `suite_finished`: Emitted once after all tests in the suite have executed.

### 2.3 JSONL Record Schema Specification

#### A. `suite_started` Event Schema
```json
{
  "timestamp": "2026-08-26T00:12:11.395411Z",
  "event_type": "suite_started",
  "suite_id": "20260826-001211-395411-7623-b7cf-28d3480a71cc-LangBashTesting.spec-SUITE",
  "spec_id": "20260826-001211-395411-7623-b7cf-28d3480a71cc-LangBashTesting.spec-0.0.1",
  "suite_name": "Bash Test Suite",
  "runner": "bats-core",
  "runner_version": "1.11.0",
  "total_planned": 12,
  "environment": {
    "hostname": "build-host",
    "kernel": "Linux 6.x",
    "user": "developer",
    "bash_version": "5.2.x"
  }
}
```

#### B. `test_case` Event Schema
```json
{
  "timestamp": "2026-08-26T00:12:12.104523Z",
  "event_type": "test_case",
  "suite_id": "20260826-001211-395411-7623-b7cf-28d3480a71cc-LangBashTesting.spec-SUITE",
  "test_id": "BT-001",
  "test_name": "bwrap-enhanced exits with error when root dir is missing",
  "status": "PASS",
  "duration_ms": 42.15,
  "exit_code": 0,
  "stdout": "",
  "stderr": "",
  "error_message": null,
  "assertions_count": 2,
  "metadata": {
    "file": "src/test/hanaden-bwrap-enhanced/test_root_validation.bats",
    "line": 15,
    "tags": ["unit", "fast", "preflight"]
  }
}
```

#### C. `suite_finished` Event Schema
```json
{
  "timestamp": "2026-08-26T00:12:15.891230Z",
  "event_type": "suite_finished",
  "suite_id": "20260826-001211-395411-7623-b7cf-28d3480a71cc-LangBashTesting.spec-SUITE",
  "status": "PASS",
  "duration_total_ms": 3786.78,
  "summary": {
    "total": 12,
    "passed": 12,
    "failed": 0,
    "skipped": 0,
    "errored": 0
  }
}
```

### 2.4 Status Enum Values

| Status | Meaning |
|---|---|
| `PASS` | All assertions within the test succeeded. |
| `FAIL` | One or more assertions failed or unexpected non-zero exit occurred. |
| `SKIP` | Test was skipped via `skip "reason"`. |
| `ERROR` | Harness/setup failure, unhandled runtime exception, or harness timeout. |

## 3. TAP to JSONL Formatting Pipeline

`bats-core` natively outputs TAP (Test Anything Protocol) or custom formatter streams. Hanaden test runners MUST bridge `bats-core` execution into compliant `jsonl` streams using one of the following methods:

1. **Native Bats JSON/Formatter Plugin:** Utilizing a custom bats formatter plugin (e.g. `bats --formatter jsonl`).
2. **Streaming TAP Transformer:** Piping TAP output through a deterministic transformer tool (e.g. `bats --tap ... | tap-to-jsonl`).
3. **Structured Test Runner Wrapper:** A dedicated bash wrapper script that orchestrates `bats` execution and writes to the configured `.jsonl` destination file.

## 4. Constraint Matrix

| ID | Constraint | Severity | Verification Method |
|---|---|---|---|
| C-BASH-001 | All Bash test suites MUST execute under `bats-core`. | FATAL | Runner inspection & test suite execution |
| C-BASH-002 | Test execution reports MUST be emitted in valid JSONL format. | FATAL | JSON schema validation of each emitted line |
| C-BASH-003 | Each JSONL line MUST be self-contained and parseable independently. | FATAL | Line-by-line `jq` / JSON parser pass |
| C-BASH-004 | Failed tests MUST capture `duration_ms`, `exit_code`, and `stderr`/error details. | HIGH | Inspection of failure records in JSONL |
| C-BASH-005 | Tests MUST NOT alter global host environment or leave untracked tempfiles. | FATAL | Pre/post-test filesystem state check |
| C-BASH-006 | Anti-reward-hacking: Tests MUST test real execution behavior, not surface text matching. | FATAL | Mutation & Sabotage tests |

---

## 5. Anti-Reward-Hacking & Quality Guards

In accordance with Hanaden Governance Rules:
- **The Sabotage Test:** If the underlying bash implementation is removed or disabled, the bats test MUST fail.
- **The Mutation Test:** Deliberate fault injection into the tested bash logic MUST produce a `FAIL` status record in the emitted JSONL.
- **The Stranger Test:** Test specifications and JSONL fields MUST be self-explanatory and derivable purely from runtime behavioral requirements without hidden conventions.

## 6. Measurement and Verification Commands

```bash
# Execute bats test suite and emit to jsonl:
bats --formatter tap src/test/hanaden-bwrap-enhanced/*.bats | rtk_tap_to_jsonl > test-results.jsonl

# Validate jsonl line format:
cat test-results.jsonl | while read -r line; do echo "$line" | jq . > /dev/null; done

# Query failed test cases from JSONL:
jq -c 'select(.event_type=="test_case" and .status=="FAIL")' test-results.jsonl
```
