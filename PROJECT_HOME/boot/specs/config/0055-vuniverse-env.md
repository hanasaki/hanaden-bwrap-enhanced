
> **Vuniverse** (n.) — *Hanaden term.* The complete, designed operational environment
> inside a vuniverse backend boundary. Not just filesystem isolation (jail) or process restriction
> (sandbox) — the vuniverse is everything: env vars, toolchain, identity, processes,
> shell config, ephemeral state. It is **built from config specs**, not inherited.
> Each conversation gets its own vuniverse. The daemon is the vuniverse's kernel.

## Vuniverse Environment Configuration

### 1. Env Var Provenance

Every env var in the vuniverse has exactly one source:

```toml
[env.provenance]
# Three sources:
#   "host"      — passed through from host env at backend launch (--clear-env allowlist)
#   "config"    — defined in this file, static value
#   "computed"  — derived at boot from other config/runtime values

HOME              = "config"
USER              = "config"
PATH              = "computed"       # built from toolchain + lang profile
SHELL             = "config"
TERM              = "host"           # pass through for terminal compat
LANG              = "host"           # locale
HANADEN_ENV       = "host"           # dev/prod — drives lang_choice (default: "dev")
HANADEN_CONV_ID   = "host"           # AI_CONV_ID from agent
HANADEN_REGEN_N   = "computed"       # incremented on each self-regen execve
HANADEN_BOOT_TS   = "computed"       # timestamp of initial boot (survives regen)
HANADEN_PID       = "computed"       # $$
HANADEN_LANG      = "computed"       # active lang from lang profile
```

### 2. Static Env (config source)

```toml
[env.static]
HOME   = "/home/sandbox-user"
USER   = "sandbox-user"
SHELL  = "/bin/bash"
LC_ALL = "C.UTF-8"
```

### 3. Host Passthrough (allowlist)

```toml
[env.host_passthrough]
# ONLY these vars are passed from host into the vuniverse.
# Everything else is stripped (bwrap --clear-env).
# Missing vars on host → silently omitted (not FATAL).
allowed = [
    "TERM",
    "LANG",
    "HANADEN_ENV",
    "HANADEN_CONV_ID",
    "AI_CONV_ID",
    "DISPLAY",
]

# HANADEN_ENV default if missing on host:
HANADEN_ENV_default = "dev"
```

### 4. Computed Env (built at boot)

```toml
[env.computed]
# Built dynamically by the daemon at boot.
# Formulas reference other config values.

PATH = """
    EPHEMERAL_HOME/bin
    : MISE_BIN_DIR
    : RTK_BIN_DIR
    : UV_BIN_DIR
    : /usr/local/bin
    : /usr/bin
    : /bin
"""
# Collapsed to single line, no spaces, at boot.

HANADEN_REGEN_N = "0"
# Incremented by +1 on each self-regen execve call.

HANADEN_BOOT_TS = "$(date +%s%N)"
# Set once at initial boot. Preserved across self-regen.
# Reset on reboot (new EPHEMERAL_HOME).

HANADEN_PID = "$$"

HANADEN_LANG = "<active lang from config/0045-lang-profile.md>"
```

### 5. Self-Regen Env Mutations (execve envp)

```toml
[env.on_regen]
# What changes when the daemon calls execve for self-regen:
increment  = ["HANADEN_REGEN_N"]           # +1 each regen
preserve   = ["HANADEN_BOOT_TS", "PATH"]   # keep current value
recompute  = []                            # re-derive from config (none currently)
# All other env vars: re-read from [env.static] + [env.host_passthrough]

# IMPORTANT: self-regen uses execve (explicit envp), NOT execv (blind inherit).
# The envp array is built from this spec at each regen cycle.
```

### 6. Persistent Bash Environment

```toml
[bash.env]
# Persistent bash inherits the daemon's full env, PLUS these:
HISTFILE    = "/dev/null"
PS1         = "\\[vuniverse:\\w\\]$ "
BASH_ENV    = ""
```

### 7. Dynamic .bashrc Template

The daemon writes this to `EPHEMERAL_HOME/home/sandbox-user/.bashrc` at boot.
Built from config values — not hand-edited.

```toml
[bash.bashrc]
template = """
# Auto-generated by hanaden-daemon at boot -- DO NOT EDIT
# Source: config/0055-vuniverse-env.md [bash.bashrc]

export PS1='${PS1}'
export HISTFILE=/dev/null
export PATH='${PATH}'

# Active lang profile
export HANADEN_LANG='${HANADEN_LANG}'
export HANADEN_ENV='${HANADEN_ENV}'

# User extensions (optional per-conversation customization)
[ -f ~/.bashrc.local ] && source ~/.bashrc.local
"""
```

### Dependencies

```
config/0045-lang-profile.md        → provides: active lang, interpreter
config/0050-lang-profile-*.md      → provides: per-lang specifics
config/0055-vuniverse-env.md       → THIS FILE
config/0058-vuniverse-backend.md   → provides: backend selection, flags
config/0060-vuniverse-fs.md        → provides: EPHEMERAL_HOME, mounts, paths
```

### Ownership

This file owns ONLY: **what env vars exist, where they come from, how they're assembled.**

It does NOT own:
- Filesystem layout (`config/0060-vuniverse-fs.md`)
- Backend flags (`config/0058-vuniverse-backend.md`)
- Toolchain binaries (tools listed in `config/0060-vuniverse-fs.md [mounts]`)
- Lang-specific details (`config/0050-lang-profile-*.md`)
