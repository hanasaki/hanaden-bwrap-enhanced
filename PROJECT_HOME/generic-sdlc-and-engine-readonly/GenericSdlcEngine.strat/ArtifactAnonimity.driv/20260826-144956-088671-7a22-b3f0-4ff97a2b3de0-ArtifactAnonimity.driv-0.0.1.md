# ArtifactAnonimity: SDLC Artifact Files Lack Stable Identity

## Problem Statement

Every artifact in the SDLC hierarchy — strategies, drivers, motivators,
features, and specifications — is stored as a file. Without embedded identity,
a file's name is its only identifier. This creates three failure modes:

1. **Rename fragility.** Renaming a file for clarity breaks all cross-references
(`parent:`, `references:`, `supersedes:`) that pointed to the old name.

2. **Collision risk.** Two agents creating files simultaneously may choose the
same slug, producing a name collision with no detection mechanism.

3. **Lineage loss.** When a file is copied or moved to a new location, no
metadata tracks which file is the original and which is the derivative.

This deficit persists regardless of which solution is chosen. If the
TimestampUuidNaming motivator were removed, the pressure to solve file
identity would remain — files would still be anonymous.

## Business / Technical Impact

| Impact dimension | Current state | Target state | Delta |
|------------------|---------------|--------------|-------|
| Cross-reference integrity | Broken on rename | Stable across rename | Elimination of rename-induced breakage |
| Concurrent creation safety | Collision risk | Zero-coordination uniqueness | No naming coordination needed |
| Lineage tracking | Absent | Embedded in filename | Every file self-identifies |
