# CrossRefField: References Field For Lateral Cross-References

## Specification Statement

SDLC artifact files MAY contain a `references:` field in YAML frontmatter.
When present, it MUST be a YAML list. Each entry MUST be either:
- A `filename-id` string that resolves to an existing file in the tree, OR
- A valid URL (http:// or https://)

The `references:` field is distinct from `parent:` — parent captures vertical
hierarchy, while references capture lateral relationships (e.g., a SPEC that
references another SPEC in a different subtree).

## Rationale

Lateral references enable non-hierarchical relationships between artifacts.
A specification may reference another specification in a different subtree
when they share a constraint or dependency. Without a structured references
field, these relationships would exist only in prose and be invisible to tooling.

## Constraints

| Constraint | Value | Condition |
|------------|-------|-----------|
| references is a YAML list | Must be list type when present | When field exists |
| Each entry is filename-id or URL | String format validated | Always |
| filename-id entries resolve | File must exist | Always |
| URL entries are valid | http:// or https:// prefix | Always |

## Leaf Value

> 🛑 **Primitive** — terminal specification.

**Value:** `references: [filename-id | URL, ...]` (list)
**Source:** All Hanaden templates — references field

## Measurement Method

```bash
# Validate references: field entries
FILE="$1"
python3 -c "
import yaml, sys, os
with open('$FILE') as f:
parts = f.read().split('---')
fm = yaml.safe_load(parts[1])
refs = fm.get('references', [])
if refs is None:
sys.exit(0)
for ref in refs:
if ref.startswith('http://') or ref.startswith('https://'):
print(f'URL: {ref}')
else:
print(f'filename-id: {ref}')
"
```
