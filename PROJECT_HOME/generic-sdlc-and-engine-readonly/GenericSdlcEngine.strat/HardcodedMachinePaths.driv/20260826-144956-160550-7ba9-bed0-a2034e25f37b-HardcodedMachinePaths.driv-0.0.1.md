# HardcodedMachinePaths: Scripts Contain Non-Portable Absolute Paths

## Problem Statement

Source files across the project reference absolute filesystem paths that are
specific to a single developer's machine. When the project is cloned to a
different machine, checked out by a different user, or the directory layout
changes, these hardcoded paths break silently or with cryptic errors.

Common manifestations:
- `/homes/home-local/hanasaki/...` in scripts (user-specific home)
- `/etc/...` paths assumed to exist on the host
- `src/main/...` paths inlined in `src/test/...` files (cross-tree leakage)

This deficit persists regardless of solution approach. The pressure to
eliminate hardcoded paths exists independently of the specific portability
mechanism chosen.

## Business / Technical Impact

| Impact dimension | Current state | Target state | Delta |
|------------------|---------------|--------------|-------|
| Portability | Works on 1 machine only | Works on any machine | 100% host-independence |
| Onboarding time | Manual path fixup on clone | Zero fixup needed | Eliminated |
| Cross-tree coupling | Test files import main paths | Indirection only | Decoupled |
