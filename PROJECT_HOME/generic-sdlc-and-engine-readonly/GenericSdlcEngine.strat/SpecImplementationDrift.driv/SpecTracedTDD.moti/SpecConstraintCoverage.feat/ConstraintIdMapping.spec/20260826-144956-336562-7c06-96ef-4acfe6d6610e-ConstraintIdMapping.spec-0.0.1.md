# ConstraintIdMapping: Constraint ID Maps To Test ID

## Specification Statement

Each row in a spec's Constraints table carries an implicit constraint ID
(the constraint text). The Test Suite section MUST contain at least one test
row whose description references this constraint. The mapping is validated
by checking that every constraint has at least one corresponding test.

## Rationale

Without explicit mapping, it is impossible to determine which tests validate
which constraints. A constraint without a test is an unverified claim.

## Constraints

| Constraint | Value | Condition |
|------------|-------|-----------|
| Each constraint has ≥1 test | Coverage check | Always |
| Test description references constraint | Text match | Always |

## Leaf Value

> 🛑 **Primitive** — terminal specification.

**Value:** Constraint → Test mapping exists

## Measurement Method

```bash
# Count constraints vs tests in a spec file
CONSTRAINTS=$(grep -c '| .* | .* | .* |' "$SPEC_FILE" | head -1)
TESTS=$(grep -c '| .* | .* | .* | .* | .* |' "$SPEC_FILE" | head -1)
echo "Constraints: $CONSTRAINTS, Tests: $TESTS"
```
