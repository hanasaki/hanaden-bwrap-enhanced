# TddStateTracking: TDD State Enum Tracks Test Lifecycle

## Specification Statement

The `tdd.state` field MUST be one of the following enum values:

- `NOT_STARTED` — no test written yet
- `RED` — test written but fails (spec requirement not yet implemented)
- `GREEN` — test passes (spec requirement implemented)
- `REFACTOR` — code being refactored while maintaining green tests
- `PASS` — test passes and code is production-ready

The state machine transitions are: NOT_STARTED → RED → GREEN → REFACTOR → PASS.
Backward transitions are allowed (e.g., GREEN → RED on regression).

## Rationale

The tdd.state field makes the test lifecycle visible in the spec document
itself. A stakeholder reading the spec can immediately see whether it has
been verified, without searching for test results.

## Constraints

| Constraint | Value | Condition |
|------------|-------|-----------|
| tdd.state is valid enum value | One of 5 allowed values | Always |
| NOT_STARTED when no test exists | tdd.test-file = null | Initial state |
| RED when test fails | Test exists but fails | After test written |
| GREEN when test passes | Test passes | After implementation |
