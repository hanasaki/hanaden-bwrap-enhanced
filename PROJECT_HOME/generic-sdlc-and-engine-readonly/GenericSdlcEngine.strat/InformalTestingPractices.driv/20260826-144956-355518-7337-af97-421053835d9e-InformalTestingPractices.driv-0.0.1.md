# InformalTestingPractices: Testing Is Ad-Hoc Ungated and Inconsistent

## Problem Statement

The project lacks formal testing conventions. Tests exist for some components
but not others. When tests exist, they produce output in inconsistent formats
(some print PASS/FAIL, some use exit codes, some produce TAP). There is no
test gating — code can be committed without running tests. Test IDs are not
mapped to specification constraints.

This deficit creates two risks:
1. **Silent regressions.** Without consistent test execution, regressions can
enter the codebase undetected.
2. **Unmeasurable coverage.** Without a standard output format, it is impossible
to aggregate test results across components.

## Business / Technical Impact

| Impact dimension | Current state | Target state | Delta |
|------------------|---------------|--------------|-------|
| Test coverage | Partial and ad-hoc | Consistent and gated | 100% spec coverage |
| Output format | Inconsistent | Standardized JSONL | Machine-parseable |
| Test gating | None | Pre-commit gate | No unvetted commits |
