# TestCaseSchema: Each test_case record MUST contain test_id, description,

## Specification Statement

For each test case executed, the suite MUST emit a `test_case` JSONL record:
- `type`: `"test_case"`
- `test_id`: unique test ID (e.g., `ROR-001`)
- `description`: human-readable description
- `status`: one of `"PASS"`, `"FAIL"`, `"SKIP"`
- `duration_ms`: execution time in milliseconds
- `constraint_id`: the spec constraint this test validates
- `error`: error message (when status = FAIL, null otherwise)

## Rationale

The test_case record is the atomic unit of test reporting. Every test
execution produces exactly one test_case record.

## Constraints

| Constraint | Value | Condition |
|------------|-------|-----------|
| type = test_case | Exact string | Always |
| status ∈ {PASS, FAIL, SKIP} | Enum validation | Always |
| duration_ms ≥ 0 | Non-negative integer | Always |
| constraint_id present | Non-empty string | Always |
