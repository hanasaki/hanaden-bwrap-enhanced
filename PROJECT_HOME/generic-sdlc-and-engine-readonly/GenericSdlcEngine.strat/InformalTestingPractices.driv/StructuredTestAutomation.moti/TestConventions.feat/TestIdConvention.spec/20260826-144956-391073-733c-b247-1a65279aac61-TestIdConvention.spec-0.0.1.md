# TestIdConvention: Every test case MUST have an ID that maps to a spec

## Specification Statement

Every test case MUST be identified by a unique ID that maps to a specific
constraint in a specification document. The ID format is:
`<SPEC-SLUG>-<NNN>` (e.g., `ROR-001`, `FF-003`).

This mapping enables automated coverage verification: for any spec, the tool
can enumerate which tests validate which constraints.

## Rationale

Without test-to-constraint mapping, test results cannot be traced back to
the specifications they validate.

## Constraints

| Constraint | Value | Condition |
|------------|-------|-----------|
| Test ID format: SLUG-NNN | 3-letter slug + 3-digit number | Always |
| Every test ID maps to a spec constraint | Bijective mapping | Always |
