STEP 0 — MANDATORY PROMPT (ask before executing):
  Ask the user exactly this question:

    "How many test suite runs should be performed?
       1        — Single run, no feedback loops (DEFAULT)
       N        — Fixed N runs with TDD feedback between each
       converge — Run until 100% pass is stable (2 consecutive clean runs),
                  or HALT if failures are not converging"

  If the user does not answer or says 'default': MODE=SINGLE (N=1).
  If the user gives a number N: MODE=FIXED, RUNS_REQUESTED=N.
  If the user says 'converge' / 'tdd' / 'convergence': MODE=CONVERGENCE.

STEP 1 — SOURCE OF TRUTH (establish before any test run):
  - Reverse-engineering: code is SST.
  - Greenfield TDD: specs are SST.
  - Both exist: code overrules spec on conflict; document all conflicts.
  Record SST decision in section 0 of the output.

STEP 2 — TERMINATION POLICY:

  MODE=SINGLE:
    Run once. Collect all data. Fill all output sections. Done.

  MODE=FIXED:
    For run 1..N:
      1. Execute full suite. Collect all results, timestamps, verbatim failures.
      2. If run < N: root-cause analysis, fix, document every file+line changed.
      3. Repeat.
    Fill all sections including trending (section 6).

  MODE=CONVERGENCE:
    EXIT SUCCESS:
      pass_rate(run N) == 100%
      AND pass_rate(run N+1) == 100%  (two consecutive clean runs required)
      → Report CONVERGED. Fill all sections.

    EXIT HALT (drift):
      failures(N) >= failures(N-1) after fixes, OR
      failures oscillate A→B→A over 3+ runs, OR
      3+ consecutive runs with zero net improvement.
      → STOP. Fill section 11 (Drift Report). Escalate to human.
      → MUST-NOT apply more fixes after drift is detected.

STEP 3 — DATA COLLECTION (per run, mandatory):
  - Wall clock start/end timestamps (UTC, ISO 8601)
  - Per phase, per suite, per spec: pass/fail/skip count, duration ms
  - Per spec: per-assertion result, verbatim FAIL output (no paraphrasing)
  - Every change made before this run: file, lines, what, why
  - SST reference for each root cause

STEP 4 — ANTI-REWARD-HACKING:
  MUST-NOT fabricate results, timings, or outputs.
  MUST-NOT call failures "minor" or omit them.
  MUST include all skips with precise guard condition.
  MUST document every inter-run change with file+line.
  Sabotage Test: if the requirement were removed, would the test still pass?
    If yes → test is fake. Rewrite.
  Mutation Test: if a bug were introduced, would the test catch it?
    If no → test is fake. Rewrite.
  A passing report from a broken suite is a FATAL violation.

STEP 5 — Fill PART B below with real data. Replace all {{PLACEHOLDERS}}.
  For single-run mode: delete sections 6 (Trending), 7 (Feedback Loops),
  and 11 (Drift Report), or mark them "(single-run: N/A)".
